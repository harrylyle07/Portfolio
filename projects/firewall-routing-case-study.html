Case study

The firewall that wasn't the problem

A monitoring server couldn't reach a server on an isolated VLAN, and the firewall logs showed nothing. The firewall got the blame, but the real problem was routing on the source host.

Problem

The monitoring server couldn't reach a server on the isolated VLAN, and nothing was showing up in the firewall logs.

What I did

I ruled out the firewall step by step:

  • Rules
  • Zones
  • Logging
  • Packet captures
  • Even a factory reset

With the firewall ruled out, I looked at the source host. The monitoring server had no route to the VLAN, so its traffic went to the home router and was dropped there before it ever reached the firewall. That's why nothing appeared in the logs. Along the way I also found a cloned deny rule that was pointing the wrong way.

To fix it, I:

  • Added a persistent static route on the monitoring server
  • Corrected the deny rule
  • Verified isolation in both directions using the firewall logs

Result

The monitoring server could reach the server on the VLAN, and the logs confirmed the isolation was working in both directions.

Lesson: check the source host's routing table before blaming the firewall.
